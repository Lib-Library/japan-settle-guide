# 입국일 기반 일정 · 할 일 개별 페이지 UX 설계

- 작성일: 2026-11-08
- 상태: 사용자 검토 대기
- 근거 전략: `.omc/specs/deep-interview-site-growth-ux.md` (새 콘텐츠 보류, 기존 콘텐츠 활용, 지표 = 방문자 수 + 입국일 입력)

## 1. 목표

- 할 일 37개를 검색으로 찾을 수 있게 각자 페이지를 준다 (방문자 수).
- 들어온 사람이 입국일을 넣고 자기 마감일을 보게 만든다 (실사용).
- 새 글은 쓰지 않는다. 기존 할 일 데이터·체크 기능·디자인 토큰(KRDS)을 그대로 쓴다.

## 2. 기한 데이터

현재 `deadline`은 표시용 문장이다. 날짜 계산을 위해 tasks 프론트매터에 **선택 필드 `due`** 를 추가한다. 기존 `deadline` 문장은 그대로 두고 화면에 함께 보여 준다.

`due`의 종류:

1. `arrival` — 입국일 기준 +N일 (예: 국제운전면허 365일). **정확**으로 표시.
2. `estimate` — 다른 사건(전입신고·입사·입주) 기준이지만 입국일 +N일로 근사. 날짜 옆에 **"예상"** 배지와 원래 `deadline` 문장을 함께 표시.
3. `before-arrival` — 입국일 -N일 (입국 전 준비). "입국 N일 전" 표시.
4. `yearly` — 달력 날짜(예: 확정신고 2/16~3/15, 주민세 6월). 월·일과 함께 "입국한 해 기준 몇 년 뒤"(0 = 그해, 1 = 다음 해)를 적는다. 출처 문장이 "다음 해"면 1, "연말"이면 0. 기간형(2/16~3/15)은 마지막 날을 마감일로 쓴다.
5. 필드 없음 — 날짜로 바꿀 수 없는 항목. 날짜를 만들지 않고 `deadline` 문장만 표시.

규칙
- 어떤 항목을 어느 종류로, 며칠로 할지는 해당 항목의 공식 출처에 적힌 기한에서만 정한다. 출처에 없는 숫자는 쓰지 않고 필드를 비운다.
- 근사값 N은 출처의 기한 그대로(예: "14일 이내" → 14). 여유를 임의로 빼거나 더하지 않는다.
- 스키마 검증은 `src/content.config.ts`에 추가해 `npm run build`에서 잡는다.

## 3. 입국일 저장

- localStorage 키 `jsg:arrival:v1`, 값 `YYYY-MM-DD`. 기존 `jsg:progress:v1`은 건드리지 않는다.
- 저장소를 못 쓰는 환경(시크릿 모드 등)에서도 이번 방문 동안은 동작하고, 오류로 페이지가 깨지지 않는다 (`checklist.ts`와 같은 방식).
- 다른 탭에서 바꾸면 `storage` 이벤트로 반영한다.

## 4. 화면

### ① 입국일 입력칸 (`ArrivalInput` 부품, 홈·할 일 페이지·내 일정 공용)

입력 전
```
내 입국일 기준으로 마감일 보기
[ 날짜 선택 ]  [보기]
입력한 날짜는 이 브라우저에만 저장돼요
```
입력 후
```
입국일 12월 1일 · 입국까지 23일   (또는 "입국 후 9일째")
[내 일정 보기 →]  [바꾸기]
```
- `<input type="date">` + 보이는 라벨 (placeholder만으로 라벨을 대신하지 않음).
- 미래 날짜 허용 (입국 전 사용자). 빈 값으로 [보기]를 누르면 입력칸 바로 아래에 안내 문구.
- [바꾸기]는 입력 상태로 되돌린다. 삭제도 여기서 가능.
- 홈에서는 기존 시기 선택(PhasePicker) **위**에 둔다.

### ② 내 일정 (`/my/`)

```
입국 후 9일째                     [입국일 바꾸기]
[휴대폰 캘린더에 전부 넣기]

지난 기한 (1)
 □ 재류카드 받기 — 12/1 · 8일 지남
이번 주 (2)
 □ 전입신고 — 12/15까지 · 6일 남음 [예상]
다가오는 일 (5)   ▸ 펼치기
날짜 없는 일 (4)  ▸ 펼치기
완료한 일 (3)     ▸ 펼치기
```
- 묶음 순서: 지난 기한 → 이번 주(7일 이내) → 다가오는 일 → 날짜 없는 일 → 완료.
- 체크칸은 기존 진행 상황과 같은 데이터(`data-task-id`)를 쓴다. 체크하면 "완료한 일"로 옮겨 간다.
- 상태는 색 + 글자("지남", "남음")로 함께 표시한다.
- 입국일이 없으면 ① 입력칸과 예시 화면(흐리게)을 보여 준다. 빈 화면을 두지 않는다.
- 선택(`optional`) 항목은 "선택" 배지를 유지한다.
- 사이드바에 "내 일정" 링크를 홈 바로 아래에 추가한다.

### ③ 할 일 개별 페이지 (`/tasks/<파일명>/`)

```
입국 후 2주 이내 › 전입신고          (시기 경로)
전입신고하기  転入届(덴뉴토도케)
┌ 내 마감일 ─────────────────────┐
│ 12월 15일까지 · 6일 남음 [예상]   │
│ 기준: 살 곳을 정한 날부터 14일 이내 │
│ [캘린더에 넣기]  □ 완료           │
└────────────────────────────────┘
어디서 / 언제까지 / 준비물 / 본문 / 출처
[← 이전 할 일]   [다음 할 일 →]       (같은 시기 안, order 순)
이 시기 할 일 전체 · 내 일정 보기
```
- URL은 tasks 파일명 그대로 (파일명 변경 금지 규칙과 일치).
- 본문은 기존 `TaskCard` 내용을 펼친 상태로 재사용한다. 시기 페이지의 카드와 내용이 같아야 한다.
- 입국일이 없으면 "내 마감일" 자리에 ① 입력칸이 들어간다.
- 날짜가 없는 항목은 "내 마감일" 상자 대신 `deadline` 문장만 보여 준다.
- 페이지 제목·설명(description)은 할 일 제목과 일본어 용어로 만든다. 시기 페이지의 카드에서 이 페이지로 가는 링크를 단다.

## 5. 캘린더 추가 (.ics)

- 브라우저에서 .ics 파일을 만들어 내려받게 한다. 서버 없음.
- 하루 종일 일정, 제목 "[일본 정착] 전입신고 마감", 설명에 할 일 페이지 주소와 "예상 날짜" 여부.
- 개별 추가(할 일 페이지)와 전체 추가(내 일정, 날짜 있는 미완료 항목만)를 제공한다.
- 일정마다 고정 UID(`<파일명>@japan-settle-guide`)를 써서 다시 넣어도 중복되지 않게 한다.

## 6. 검색·측정

- `public/robots.txt`: 사이트맵 위치 명시. 개별 페이지는 사이트맵에 포함.
- 공유 미리보기용 meta(og:title/description). 이미지는 사이트 공통 1장으로 시작.
- Cloudflare Web Analytics(쿠키 없음)를 전 페이지에 추가.
- 입국일 입력 수는 통계 도구가 직접 세지 못하므로 **`/my/` 방문 수**를 대리 지표로 쓴다. 입력 후 안내 버튼이 `/my/`로 이어지게 한다.
- 카드뉴스 링크 규칙: `?utm_source=instagram&utm_campaign=<카드뉴스 주제>` (문서로만 정리).

## 7. 접근성·모바일

- 터치 영역 44px 이상, 1열 레이아웃, 3열 이상 표 없음.
- 날짜는 "12월 15일"처럼 한국어로 쓴다. `01/02` 같은 형식은 쓰지 않는다.
- 남은 일수는 페이지를 연 날 기준으로 계산하고, 시간대는 사용자 기기 기준으로 한다.
- 다크 모드는 기존 `custom.css` 방식으로 맞춘다.

## 8. 구현 방식

- 기존 패턴(Astro 컴포넌트 + `src/scripts/*.ts` 바닐라 스크립트)을 따른다. 새 프레임워크·의존성 없음.
- 날짜 계산은 순수 함수(`src/lib/due.ts`)로 분리하고, 기존 `scripts/check-initial-cost.mjs`처럼 `npm run check`에 계산 검사를 추가한다.

## 9. 하지 않는 것

새 콘텐츠, 계정·동기화, 푸시 알림, 이메일, 입사일·입주일 추가 입력, 항목별 공유 이미지.

## 10. 완료 기준

- 할 일 37개가 각자 페이지를 가지고 사이트맵에 포함된다.
- 입국일을 한 곳에서 넣으면 홈·내 일정·할 일 페이지에 같은 날짜가 반영된다.
- `estimate` 항목에는 항상 "예상" 배지와 원래 기준 문장이 함께 보인다.
- 날짜 근거가 없는 항목에 날짜가 표시되지 않는다.
- .ics를 휴대폰 캘린더에 넣었을 때 날짜가 화면과 같다.
- 기존 체크 진행 상황이 유지된다.
- `npm run build`, `npm run check` 통과.
